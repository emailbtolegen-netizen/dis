# Резервное копирование и восстановление

## Что хранится и где

| Каталог | Содержимое | Как копировать |
|---|---|---|
| `data/zhkh.sqlite` (+ `-wal`, `-shm`) | вся база: объекты, история, связи, пользователи, журнал, отчёты импорта | только встроенными средствами (ниже) — не копируйте файл работающей базы вручную |
| `data/backups/` | резервные копии базы | копировать на другой носитель/сервер |
| `data/attachments/` | загруженные документы и фото | обычное копирование файлов (rsync/robocopy) |
| `data/uploads/` | исходные Excel-файлы всех импортов | обычное копирование файлов |
| `.env` | настройки | хранить отдельно, в защищённом месте |

## Автоматические копии базы

- **Плановая** — каждые 24 ч (`BACKUP_INTERVAL_HOURS`), хранится 30 последних автоматических копий (`BACKUP_KEEP`).
- **Перед каждым применением импорта, откатом и восстановлением** — создаётся автоматически.
- Копии делаются командой SQLite `VACUUM INTO` — согласованный снимок без остановки сервера.

## Ручная копия

- В интерфейсе: «Администрирование → Резервные копии → Создать копию сейчас» (ручные копии не удаляются автоматически), там же — скачивание.
- В командной строке: `npm run backup`.

## Копирование на другой носитель (обязательно)

Копии внутри `data/backups` защищают от ошибок пользователей, но не от отказа диска. Ежедневно переносите `data/backups`, `data/attachments`, `data/uploads` на другой сервер или носитель.

Linux (cron, ежедневно в 02:30):
```bash
30 2 * * * cd /opt/zhkh/app && npm run backup >/dev/null && rsync -a --delete data/backups data/attachments data/uploads backup@nas:/backups/zhkh/
```

Windows (Планировщик заданий, PowerShell):
```powershell
cd C:\zhkh; npm run backup; robocopy C:\zhkh\data \\nas\backups\zhkh /MIR /XF zhkh.sqlite zhkh.sqlite-wal zhkh.sqlite-shm
```

## Восстановление

**Через интерфейс:** «Резервные копии → Восстановить» → ввести слово `ВОССТАНОВИТЬ`. Текущее состояние перед восстановлением автоматически сохраняется отдельной копией (`…-before-restore.sqlite`), так что восстановление можно отменить.

**Вручную (если интерфейс недоступен):**
```bash
sudo systemctl stop zhkh
cd /opt/zhkh/app/data
mv zhkh.sqlite zhkh.sqlite.broken; rm -f zhkh.sqlite-wal zhkh.sqlite-shm
cp backups/zhkh-20261012-023000-scheduled.sqlite zhkh.sqlite
sudo systemctl start zhkh
```

**Отмена ошибочного импорта** без восстановления всей базы: «История импорта → импорт → Откатить импорт». Удаляются созданные импортом записи (с возможностью восстановления), изменённые возвращаются к прежним значениям; записи, изменённые после импорта, не затрагиваются.

## Проверка копий

Раз в месяц восстанавливайте последнюю копию на тестовом компьютере (`DATA_DIR=test-data`, скопировать копию в `test-data/zhkh.sqlite`, `npm start`) и убеждайтесь, что система открывается и данные на месте.
