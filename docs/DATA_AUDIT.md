## 3. Взаимосвязи между файлами

| Связь | Способ | Результат |
|---|---|---|
| Термомодернизация → дом МЖД | нормализованный адрес (улица/мкр + № дома; «ы.а», «үй», «көшесі», «Вокзал маңы» → «Привокзальный», «э»→«е») | 75 из 75 записей связаны (77 связей: некоторые адреса встречаются в МЖД дважды); 2 — с пониженной достоверностью (без учёта блока) |
| ВЛ/КЛ → ТП | номер ТП в наименовании линии («от ТП-№2/1», «между КТПН-550/3 до КТПН-550/4») | 1102 предложенные связи |
| ВЛ/КЛ → ПС, РП | номер ПС/РП в наименовании | 24 и 132 связи |
| ТП → РП | «(2-ое пит. Ф.877 от РП-29)» | 12 связей |
| КЛ-0,4 кВ → дом МЖД | «ж/д №64» + улица из места/подзаголовка | 59 связей (достоверность 60 %) |

Все автоматические связи сохраняются со статусом «предложена»; сотрудник подтверждает или отклоняет их в карточке объекта. Подтверждённые решения сохраняются при повторных импортах.

## 4. Структура базы данных (этап 2)

СУБД — SQLite (один файл `data/zhkh.sqlite`, режим WAL). Обоснование — в README.

| Таблица | Назначение |
|---|---|
| `categories` | разделы (МЖД, ПС, РП, ТП, ВЛ, КЛ, водоснабжение…) и описание их полей (тип, единицы, исходный столбец, обязательность, конфиденциальность) |
| `objects` | единый реестр: уникальный `uid` (ATR-TP-00059), общие поля (наименование, номер, адрес, статус, балансодержатель, год, напряжение, мощность, протяжённость, координаты), `attrs` — поля категории, `raw` — исходная строка Excel без изменений, `issues` — замечания импорта, `natural_key` — ключ сопоставления, ссылка на файл/лист/строку |
| `addresses` | адресный справочник: здания и территории с нормализованным ключом |
| `object_links` | связи между объектами (тип, способ, достоверность, статус проверки) |
| `change_log` | история изменений каждого объекта (поле, старое → новое, причина, автор, импорт) |
| `source_files`, `imports`, `import_rows` | исходные файлы (SHA-256), импорты, построчный отчёт и состояние «до» для отката |
| `users`, `roles`, `sessions` | пользователи, роли с правами и доступными разделами, сессии (хранится только хеш токена) |
| `attachments` | документы и фото объектов |
| `audit_log` | журнал действий |
| `settings`, `meta` | настройки (публичный режим), счётчики идентификаторов |

## 5. Правила импорта

1. Формат листа определяется по заголовкам (МЖД, перечень энергообъектов, таблица КСК); для других файлов — ручное сопоставление столбцов.
2. Каждая строка получает **ключ сопоставления**: МЖД — нормализованный адрес; энергообъекты — раздел + класс напряжения + наименование; КСК — год + адрес. При повторе ключа в файле добавляется `#2`, `#3` — записи **не объединяются**, а помечаются как возможные дубликаты.
3. При повторной загрузке: новые ключи → «новые», совпавшие с отличиями → «изменённые» (с перечнем полей), совпавшие без отличий → «без изменений», объекты прошлых импортов этого формата, которых нет в файле, → «отсутствуют в файле» (не удаляются).
4. Записи, изменённые вручную после импорта, по умолчанию не перезаписываются.
5. Перед применением — резервная копия базы; применённый импорт можно откатить.
6. Исходные значения сохраняются без изменений; нормализованные значения (числа, мощность, номер ТП, класс напряжения) хранятся отдельно с пометкой «рассчитано».
7. Отсутствующие сведения не заполняются: поле остаётся пустым и отображается как «Не указано».
