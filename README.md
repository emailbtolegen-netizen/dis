# Цифровая информационная система ЖКХ города Атырау

Единая цифровая база объектов и инженерной инфраструктуры: реестр многоквартирных домов, электрохозяйство (ПС, РП, ТП/КТП, ВЛ, КЛ, фидеры), термомодернизация, адресный справочник, поиск, контроль качества данных, импорт Excel с отчётом и откатом, роли и журнал действий.

База наполнена реальными данными из трёх исходных файлов: **3298 записей** (1239 МЖД, 1984 энергообъекта, 75 записей термомодернизации). Подробности — в отчёте `docs/IMPORT_REPORT.md` (формируется локально командой `npm run report`).

## Быстрый старт

```bash
npm run setup && npm run build
npm run create-admin -- --login admin --name "Фамилия И.О."
npm run import-initial -- "../МЖД 1240 2025 жыл0313115516 (2).xlsx" "../Список энергообъектов за 2026  ЖКХ (2).xlsx" "../Таблица КСК 2020-2024 г!!!!!.xlsx"
npm start        # http://127.0.0.1:3000
```

## Технологический стек и обоснование

| Слой | Технология |
|---|---|
| Интерфейс | React 19, TypeScript, Vite, Ant Design 5 (локали ru_RU и kk_KZ), Recharts, Leaflet |
| Сервер / API | Node.js 24, Express 5, TypeScript (запуск без сборки), Zod (валидация), Helmet (заголовки безопасности), Multer |
| База данных | SQLite через встроенный модуль `node:sqlite`, режим WAL, миграции |
| Excel | SheetJS 0.20.3 (чтение .xlsx/.xls/.csv, формирование выгрузок) |

**Почему SQLite, а не PostgreSQL.** Для объёма ЖКХ одного города (тысячи–десятки тысяч объектов, десятки одновременных пользователей) SQLite в режиме WAL обеспечивает необходимую надёжность, но не требует отдельного сервера СУБД, администрирования и паролей подключения; резервная копия — один файл, восстановление — одна операция в интерфейсе. Доступ к БД сосредоточен в модуле `server/src/db` и сервисах; SQL написан переносимо (JSON-поля через `json_extract`), поэтому при росте нагрузки возможен переход на PostgreSQL (≈ замена слоя `db.ts` и JSON-функций на `jsonb`). Данные хранятся на сервере, а не в браузере.

## Требует настройки или уточнения

1. **Развёртывание в сети** — сервер, домен, HTTPS-сертификат (инструкция — DEPLOY.md). Система не опубликована в интернете: она запускалась и проверялась только локально.
2. **Политика доступа** — круг пользователей, состав публикуемых сведений (публичная версия выключена).
3. **Копирование резервных копий на другой носитель** — настройка cron/планировщика (BACKUP.md).
4. **Уточнение данных** (подробно — IMPORT_REPORT.md): смысл столбца R без заголовка в МЖД; отсутствие данных термомодернизации за 2023 г.; балансовая принадлежность ПС-52; дубли номеров ТП; мощность 29 РП; подозрительные площади (например, «Ауезова, 14» — 13,4 м² на 8 квартир).
5. **Реестры водоснабжения, канализации, тепловых сетей, освещения** — при наличии файлов импортируются через «Импорт Excel» с сопоставлением столбцов; для новых видов объектов — «Справочники → Новая категория».
6. **Картографический сервис** — при массовом использовании карты нужен собственный сервер тайлов или коммерческий провайдер.

## Безопасность

- Пароли — scrypt с солью; сессия — httpOnly cookie `SameSite=Strict` (+ `Secure` при HTTPS), в БД хранится только SHA-256 токена; блокировка учётной записи после 5 неудачных попыток на 15 минут и ограничение попыток с одного IP.
- Все права проверяются на сервере для каждого запроса; разделы ограничиваются ролью.
- Защита от CSRF: проверка `Origin` и обязательный заголовок `X-Requested-With`.
- Заголовки безопасности (CSP, HSTS при HTTPS и др.) через Helmet; параметризованные SQL-запросы; ключи полей проверяются по белому списку.
- Загрузка файлов: белый список расширений, проверка сигнатуры, случайные имена на диске, хранение вне веб-каталога, ограничение размера; формулы и макросы Excel не выполняются.
- Конфиденциальные поля (контакты/ФИО из таблицы КСК) скрыты от ролей без права «Просмотр конфиденциальных полей», не участвуют в полнотекстовом поиске и не могут быть опубликованы.
- Секреты в клиентском коде отсутствуют; настройки — в `.env` (не публикуется).
